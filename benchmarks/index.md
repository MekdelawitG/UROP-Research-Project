# Benchmarks

This project evaluates the effectiveness of tests generated by large language models (LLMs) across multiple Java benchmark projects. Benchmarks are selected to represent varying levels of program complexity in order to study how LLM-generated test effectiveness changes as software systems become more complex.

---

## Benchmark Purpose

Benchmarks serve as the experimental subjects used to evaluate:
- Code coverage achieved by LLM-generated tests
- Fault detection capability measured through mutation testing
- The relationship between coverage and mutation score

Using benchmarks of different complexity allows the project to assess whether LLM-generated tests scale effectively beyond simple programs.

---

## Benchmark Categories

Benchmark projects are categorized into three levels of complexity:

### Easy Benchmarks
Characteristics:
- Small codebase (low lines of code)
- Minimal or no external dependencies
- Simple control flow and program structure
- Limited number of classes and methods

Purpose:
- Validate the test generation and evaluation pipeline
- Establish baseline performance of LLM-generated tests

---

### Medium Benchmarks
Characteristics:
- Moderate codebase size
- Some external dependencies
- More complex control flow and interactions between classes
- Use of common object-oriented design patterns

Purpose:
- Evaluate how LLM-generated test effectiveness changes with increased complexity
- Observe differences between coverage and mutation score

---

### Hard Benchmarks
Characteristics:
- Large codebase
- Multiple external dependencies
- Complex control flow and object interactions
- Realistic project structure similar to production systems

Purpose:
- Assess the limits of LLM-generated test effectiveness
- Study scalability issues in both test generation and evaluation
- Identify cases where coverage may significantly diverge from fault detection capability

---

## Benchmark Selection Criteria

Benchmarks will be selected based on:
- Lines of code (LOC)
- Number of classes and methods
- Dependency count
- Project structure and modularity
- Suitability for mutation testing with PIT

Only Java projects that can be reliably built and tested using standard tools will be considered.

---

## Status

Benchmark projects have not yet been finalized.  
Final selection and classification will be completed before the experimental phase begins.

---

## Notes

If benchmark setup or mutation testing proves unstable for high-complexity projects, the experimental focus may shift toward easy and medium benchmarks, with increased emphasis on analysis depth rather than quantity.
